A charming system monitor

Monitor your Linux machines
from the terminal.

bewitch is a monitoring daemon and terminal UI for homelab servers, Raspberry Pis and VPSes. It stores CPU, memory, disk, network and hardware metrics in a local DuckDB database, so you can chart them, query them in SQL and alert on them.

$ curl -fsSL https://bewitch.dev/install.sh | sudo sh

Query your metrics in SQL

bewitch repl has tab completion, multi-line editing and .export to CSV, Parquet or JSON. The all_* views include archived Parquet data alongside the live database.

bewitch repl
bewitch> SELECT d.value AS mount,
...> round(avg(m.used_bytes * 100.0 / m.total_bytes), 1) AS pct
...> FROM disk_metrics m JOIN dimension_values d ON d.id = m.mount_id
...> WHERE m.ts > now() - INTERVAL '30 days'
...> GROUP BY mount;
mount | pct
-------+------
/ | 62.3
/home | 41.2

One URL per notification service

Chat and push services are configured with a Shoutrrr URL each, so there's no relay to run. Email goes through SMTP or the host's local mail system.

/etc/bewitch.toml
[alerts]
shoutrrr_urls = [
"discord://token@channel",
"ntfy://ntfy.sh/basement-rack",
]
[[alerts.email]]
use_mail_cmd = true
to = ["me@example.com"]

Other features

  • Process viewEvery process, sortable and searchable, with per-process disk and network I/O. Pin processes by name or glob.
  • Custom sourcesPoll Pi-hole, Home Assistant, Docker or any JSON HTTP API and chart the values. Configured in TOML.
  • Proxmox & ZFSPer-dataset ZFS I/O, SMART for pool disks, memory figures that account for the ARC, and guest stats from the Proxmox API.
  • Remote accessTLS by default, SSH-style fingerprint pinning, optional bearer token.
  • Prometheus endpointA /metrics endpoint for Prometheus and Grafana, plus a JSON API.
  • Retention & archivalPruning, compaction, daily Parquet archives and standalone snapshots.
{# ---- Scope: what it's for and how it's deployed ---- #}

Designed for a few machines, not a fleet.

Each machine runs its own daemon and keeps its own data; there's no central server, cloud account or subscription. The TUI connects to any of them, locally or over TLS. The packaged daemon runs as an unprivileged, sandboxed systemd service, and DuckDB's memory use is capped at 512 MB by default.
